# 스쿱앤십 메뉴 관리 — 와인 탭 개발 인수인계

작성: 2026-10-04 · 대상: 이 코드베이스를 이어서 개발할 개발자/AI

---

## 1. 배경

스쿱앤십(모란, 젤라또 + 와인 매장)의 **로컬 메뉴 관리 웹앱**이다. 매장 PC(Windows 11, 1920×1080)에서 상시 실행되며 알바생이 브라우저로 `http://localhost:8787/` 에 접속해 쓴다.

현재 **젤라또** 메뉴 관리는 완성·운영 중이다. 이번 작업은 같은 페이지에 **와인** 탭을 추가하는 것이다.

---

## 2. 이번에 만들 것 — 요구사항 (운영자 원문 정리)

### UI
- 현재 페이지 상단의 "스쿱앤십 메뉴 관리" 헤더 영역을 없애고, 그 자리에 **상단 탭 네비게이션: `젤라또` | `와인`**.
- **젤라또 탭**: 지금 화면 그대로 (1. 준비물, 2. 메뉴 관리).
- **와인 탭**: 일단 **메뉴 관리만**.
- 와인 메뉴 관리도 젤라또처럼 **왼쪽 = 판매중, 오른쪽 = 비활성**.
  - 판매중: 토스 포스에서 **고객용 채널 노출 ON** 인 와인.
  - 비활성: 포스에 등록돼 있지만 **고객용 채널 노출 OFF** 인 와인.
  - 단, 포스 상품 중 **와인 추천 메뉴**(예: "다양하게 바틀 추천해주세요")와 **가격이 '직접입력'인 상품**(예: "글라스 와인", "바틀 와인")은 **제외**.

### 와인 속성
이미지, 이름, 설명, 글라스 가격, 바틀 가격, 미개봉 재고 수, 개봉 병 여부.
- 어떤 속성을 목록(1뎁스)에 보여주고 어떤 것을 상세 모달에 둘지는 UX 판단으로 결정.
- 표시 이름은 최대한 간결하게.

### 기능
1. 각 와인의 **활성/비활성 전환**. 비활성으로 옮기면 포스의 **고객용 채널 노출이 OFF** 가 되어야 함.
2. **개봉 병 여부 ON/OFF**. OFF → ON 하면 **미개봉 재고 -1**. 미개봉 재고가 0이면 ON 불가.
3. 개봉 병 **OFF** = 그 병을 다 마심 (재고 수에는 영향 없음). **미개봉 재고 0 + 개봉 병 OFF** 가 되면 자동으로 **비활성으로 이동**하고 포스의 **고객용 채널 노출 OFF**.
4. **새 와인 추가**. 속성 입력(이미지는 선택). 추가하면 포스에 **무조건 상품 등록**, 고객용 채널 노출 여부는 추가할 때 선택받아 그 값으로 설정.

### 화면 이동 (포스가 다른 페이지일 때)
포스가 주문 현황 등 **다른 페이지를 보고 있어도** 기능 1~4 가 동작해야 한다.
각 작업을 시작할 때 포스를 **좌상단 ≡ → "상품 · 할인" → 카테고리 탭 "와인"** 경로로 옮긴 뒤 진행한다.
이미 그 화면이면 아무것도 누르지 않는다. 이동 중 하는 클릭은 화면 이동뿐이고 상품 데이터는 건드리지 않는다.

### 제약
- **젤라또 기능과 독립적으로** 구현 (서로 영향 없게). 젤라또 코드는 수정 최소화.
- 엔드포인트는 기존 **`http://localhost:8787/` 하나**(같은 서버, 같은 포트).
- 포스(토스 포스) 상품명/가격은 와인 장부와 OCR 로 대조되므로 이름·가격이 같은 와인으로 매칭돼야 한다.

### 참고: 포스에서 하는 일 (사람이 할 때의 경로)
포스 좌상단 ≡ → "상품 · 할인" → 상단 카테고리 탭 "와인".
- 노출 끄기/켜기: 목록 오른쪽 끝 열 **"고객용 채널 노출"** 토글 (옆의 "품절표시" 토글이 아님).
- 새 상품: 오른쪽 위 **[+ 상품 추가]** → 상품이름, 키오스크·테이블오더용 이름(한글/영문), 한글설명, 카테고리 칩 "와인", 기본가격 → [등록]. 창 맨 위에 "고객용 채널 노출" 토글(기본 ON), 사진은 "이미지 추가".

## 3. 현재 구조

```
automation/
├─ server.mjs              # 메뉴 관리 서버 (HTTP 8787 + SSE) — 젤라또용
├─ web/index.html          # 단일 페이지 UI (바닐라 JS, Pretendard, 서버가 매 요청 파일을 읽음)
├─ web/favicon.(png|ico)
├─ lib/
│  ├─ ops.mjs              # 젤라또 작업 실행기 (피그마 → 배민 → 쿠팡 순서, 채널별 진행 기록)
│  ├─ wsbridge.mjs         # 로컬 WebSocket 브리지 (피그마 플러그인 3055 / 크롬 확장 3056)
│  ├─ names.mjs            # 피그마명 ↔ 배달앱 옵션명 매칭 (menu-aliases.json)
│  ├─ secrets.mjs          # DPAPI 암호화된 로그인 정보 읽기 (.secrets/*.cred — 인수인계 자료에서 제외)
│  └─ paths.mjs
├─ channels/               # 젤라또 채널: figma.mjs · baemin.mjs · coupang.mjs
├─ figma-plugin/           # 피그마 메뉴판 플러그인 (젤라또 메뉴판 편집)
├─ chrome-extension/       # 배민·쿠팡을 평소 크롬에서 조작하는 확장
├─ menu.mjs / ../menu.ps1  # 젤라또 CLI (서버가 켜져 있으면 서버 경유)
├─ run-server.ps1          # 서버 실행기 (죽으면 5초 뒤 재시작)
├─ install-autostart.ps1   # 시작프로그램 등록 (로그인 시 자동 실행)
├─ logs/                   # server.log, jobs.json (작업 기록 — 재시작해도 유지)
└─ tosspos/                # ★ 토스 포스 화면 자동화 (와인용으로 검증 완료)
   ├─ pos_screen.py        # 캡처 + OCR + 클릭 + 입력
   ├─ ocr.ps1              # Windows 내장 OCR(한국어) → JSON
   └─ openapi.mjs          # 토스플레이스 Open API 조회 클라이언트 (현재 403 — 앱 검수 전이라 미사용)
```

### 서버(server.mjs) 동작 요약
- `GET /` → `web/index.html`, `GET /favicon.*`
- `GET /api/events` → SSE `state` 이벤트 (상태 바뀔 때마다 전체 스냅샷 push)
- `GET /api/state`, `GET /api/jobs/:id`, `GET /api/health`
- `POST /api/jobs` `{cmd, name, desc, …}` → 작업 큐(한 번에 하나씩 순차 실행) / `POST /api/jobs/:id/retry`
- **모든 POST 는 헤더 `x-menu-app: 1` 필수** (다른 사이트의 몰래 호출 방지). `127.0.0.1` 에만 바인딩.
- 작업 기록은 `logs/jobs.json` 에 저장 → 서버 재시작 후에도 화면에 남음.
- 서버 수정 후 재시작: `server.mjs` node 프로세스만 종료하면 `run-server.ps1` 이 5초 뒤 다시 켬. `index.html` 은 재시작 불필요.

### UI(index.html) 요약
- 상태 `S`(SSE 로 받은 서버 스냅샷) → `render()` 가 섹션별로 다시 그림.
- 디자인 토큰: 배경 `#f6f4f1`, 브랜드 `#862727`, 초록 `#1f9d55`, 빨강 `#d64545`, 카드 radius 14px, Pretendard.
- 하단 "작업 현황" 도크: 진행 중이면 그 작업 1건, 아니면 최근 1건만 표시.

## 4. 토스 포스 자동화 (`tosspos/pos_screen.py`) — 검증된 기능

토스 포스는 Electron 앱이며 **디버깅 포트·접근성 트리·Open API 쓰기 모두 막혀 있어**, 화면 이미지 방식으로 구현했다.
실행: 프로젝트 루트에서 `python automation/tosspos/pos_screen.py <명령>` (Python 3.12 + pywin32 + Pillow).

| 명령 | 설명 | 상태 |
|---|---|---|
| `nav` | **포스를 '상품 · 할인 > 와인' 화면으로 이동** (다른 페이지여도 ≡ → 상품 · 할인 → 와인 탭) | ✅ 실사용 성공 |
| `all` | 와인 탭 전체를 스크롤하며 읽어 JSON 반환: `name, price, priceText, expose, soldOutMark, y` | ✅ 16개 정확 |
| `wines` | 현재 보이는 화면만 읽기 | ✅ |
| `expose "<와인명>" on|off [가격]` | 고객용 채널 노출 토글 설정 (이미 같으면 클릭 안 함) | ✅ 실사용 성공 |
| `add '<json>' [--no-submit]` | 상품 추가. json = `{name, kioskName, kioskNameEn, desc, category, price}` | ✅ 실사용 성공 (사진 업로드 미구현) |
| `capture <파일>` / `peek <스크롤칸> <파일>` | 캡처 / 스크롤 후 캡처+OCR | ✅ |

Python 함수: `capture()`, `ocr(im)`, `wines(im)`, `all_wines()`, `match_row(rows, name, price)`, `set_expose(name, on, price)`, `add_product(spec, submit=True)`, `Foreground()` (컨텍스트 매니저), `ensure_wine_list()`.

### 꼭 알아야 할 함정 (모두 실제로 겪고 해결한 것)
1. **포스가 다른 창에 가려지면 화면을 다시 그리지 않는다** → 스크롤·클릭이 반영 안 되고 캡처도 예전 화면. 작업 동안 `Foreground()` 로 포스를 앞으로 띄우고 끝나면 원래 창 복귀.
2. **OCR 오타**: 가비→가리, 빰빠네오→참빠너모, 무알콜→무일를, 10,000→1다000. → `match_row` 가 이름 유사도(≥0.6, 1·2등 차 ≥0.1) + **가격 일치**로 매칭. 와인 장부의 정식 이름과 대조할 것.
3. **흰 글자(선택된 '와인' 탭, 파란 [등록] 버튼)는 OCR 이 못 읽음** → 탭은 "읽히지 않은 탭 1개 = 선택된 탭" 소거법, [등록]은 [닫기] 오른쪽 위치 + 버튼 색(활성 `(49,130,246)` / 비활성 `(202,223,253)`).
4. **클립보드 붙여넣기는 불안정**(포스가 늦게 읽어 이전 내용이 들어감, 클립보드 잠김) → `SendInput` 유니코드 직접 입력.
5. 입력칸에 값이 있으면 안내문구가 사라져 위치를 못 찾음 → **라벨 기준 상대 위치**로 클릭.
6. 숫자 칸에 **깜빡이는 커서**가 OCR 을 방해 → 라벨 클릭으로 포커스 해제 후 확인.
7. 상품 등록 직후 "방금 등록한 상품을 알려보세요" **배너가 떠서 레이아웃이 ~70px 밀림** → 고정 좌표 금지, 머리줄/탭 위치를 매번 찾음.
8. 스크롤은 `WM_MOUSEWHEEL` PostMessage(커서 이동 없음). 부드러운 스크롤이라 첫 줄이 안 바뀔 때까지 반복.
9. 토글 ON/OFF 판별: 토글 중심 가로 45px 안 파란 픽셀(`b>200, r<120`) 8개 초과면 ON.
10. **포스가 다른 페이지에 있으면 아무것도 못 한다** → `ensure_wine_list()` 가 화면을 먼저 맞춘다.
    ≡ 는 '테이블' 글자 기준 상대 위치(배너로 밀려도 안전), 메뉴의 '상품 · 할인' 은 섹션 머리글 '상품' 과
    헷갈리지 않게 길이·유사도로 구분('성품•할인' 오타 대응).
11. **카테고리 탭 '와인' 은 선택 여부와 상관없이 OCR 이 거의 못 읽는다**(두 글자라서). → 탭 순서
    (전체·젤라또·메뉴·와인·무알콜·위스키)를 알고 있으므로 **앞뒤로 읽힌 탭 사이의 가운데**를 누른다.
12. **선택된 탭이 흰 글자라도 가끔 오타로 읽힌다**('젤라또'→'질라또'). 소거법만 쓰면 엉뚱한 답이 나오므로
    `selected_tab()` 은 **선택 배경색 구간(78,89,104)을 먼저 보고** 그 위의 글자를 유사도로 맞춘다.
13. 모든 클릭 전 안전 확인: 상품>와인 화면인지, 행이 하나로 확실히 매칭되는지, 클릭 좌표가 허용 영역 안인지 → 아니면 **클릭하지 않고 예외**. 클릭 후 다시 읽어 결과 확인.

### 현재 포스 와인 목록 (2026-10-04 기준, 16개)
판매중(노출 ON): 테스트(100,000 — 테스트용, 삭제 필요), 가비-화이트 12,000, 샤또 라로즈-레드 9,000, 르리트롱-내추럴 화이트(오렌지) 12,000, 이그리노-내추럴 레드 9,000, 퇴플러-레드 14,000, 그란 셀로 GST-레드 10,000, 무알콜 와인-화이트(샤도네이, 프랑스) 8,000, 무알콜 와인-레드(까르베네 쇼비뇽, 프랑스) 8,000, 스타보로우-화이트 10,000, 줄리엣-화이트 12,000
비활성(노출 OFF): 칼뢰벤-화이트 12,000, 빰빠네오-내추럴 화이트(오렌지) 11,000
제외 대상: 다양하게 바틀 추천해주세요(0), 글라스 와인(직접입력), 바틀 와인(직접입력)

※ 포스에는 상품당 **가격이 하나**(기본가격)만 있다. 글라스/바틀 가격을 포스와 어떻게 대응시킬지는 설계 시 정해야 함 (운영자에게 확인 권장).

## 5. 개발 규칙
- 작업 후 **QA 필수**: 화면 캡처로 확인, 기존 젤라또 기능 회귀 없는지 확인.
- 젤라또 쪽 테스트: `node automation/test/figma-plugin.test.cjs <피그마 node.json>`.
- 비밀정보(`.secrets/`, `.figma-token`)는 절대 커밋·출력 금지.
- 사용자 안내·UI 문구는 한국어, 알바생도 이해할 수 있게.
